# 答案

### Q1
**都没变。** `Swap` 里的 `a = b` 只是把手里那个**遥控器复印件**扔了、换了一个 —— 外面那两个变量指着的东西没动。`pieces[0,0]` 从头到尾还指着 `p1`。
> 判据：**赋值改的是"指向"，方法改的是"对象"。** 只有调 `SetPos`/`Add` 这类方法，外面才看得见。

### Q2
1. 🔴 **`foreach` 里 `matchs.Remove(piece)`** → 抛 `InvalidOperationException: Collection was modified`。遍历时不能改集合。
2. 🔴 **删的顺序反了** —— 先 `pieces[x,y] = null` 再 `Destroy` 本身没错，但它和 `foreach` 一起就变成"边遍历边改源集合"。
3. 🟠 **语法错**：`piece.x` / `piece.y` 是你 `Piece` 上的字段（`x`、`y`），不是属性 `x()`，要用 `piece.x`；这一条如果编译过说明只是示意。
4. 🟠 那个 `if (pieces[...] == null) continue;` 是**必要的守卫**（洞的防御）—— 这一条是对的，别把它一起删了。
**正解**：先收集要删的，循环结束后统一删；或用倒序 `for`。

### Q3
1. **凭空消失** —— 没有任何缩小动画。
2. Console 里会出现 DOTween 的三条报错：
   - `Tween startup failed (NULL target/property -); the tween will now be killed`
   - `The object of type 'Transform' has been destroyed. Your script should either check if it is null or you should not destroy the object.`
   报错原文里 **"you should not destroy the object"** 就是答案。
3. 挪到 `yield return new WaitForSeconds(0.5f);` **之后**。
> 两个机制：`Destroy` 只是**标记**，真正销毁在**当帧结束时**；而 DOTween 的 tween 创建后要等**下一个 Update** 才启动。同一帧里先建 tween 再 `Destroy` → 下一帧启动时 target 已经是 null。

### Q4
1. 方块不掉：`DropPiece` 在你**调用它的那一刻**就遍历数组找空洞 —— 但那时 `RemovePiece` 还没跑，数组里那三个方块**还在**，找不到任何洞 → 返回一个**空 Sequence**。
2. 不生成：同理，`GeneratePiece` 调用时数组里**没有 null** → 一个都不生成。
3. **规则：每一步的"创建"必须发生在上一步真正结束之后。** 原来的三层 `OnComplete` 虽然难读，但它把"时机"和"位置"绑在一起了；拍成直线时位置对了、时机丢了。
> 补充：`DOTween.Sequence()` 一创建就开始播放，不需要手写 `.Play()`。

### Q5
1. **第 32 行崩**，报 `NullReferenceException`。因为 `Resources.Load` 找不到文件时**不报错，只是返回 null**，然后 `json.text` 空引用。
2. **不会。** 报错信息里完全没有"文件"两个字，只有 `NullReferenceException`。
3. 新手会死盯第 32 行，反复查 `JsonUtility.FromJson` 的语法、检查 JSON 格式 —— 浪费 1~2 小时，方向完全错。
4. 加判空 + 明确报错：
```csharp
if (json == null) { Debug.LogError("题库文件没找到！检查 Resources/JSON/data.json"); return; }
```
> 记住：**报错的位置 ≠ 出错的位置。**

### Q6
1. 存档是一段**文本**，文本只能装下"身份"（名字），装不下"内容"（整个资产）。
2. **`PieceStyle` 里有一个 `Sprite` 字段，它也是 asset 引用。** 序列化时只会写进一个 instanceID —— 这个编号只在本次运行/当前编辑器有效，下次打开指向的东西就变了。
> 结果就是：读档成功、Console 干净、分数和棋盘都对，**但所有方块变白块或花屏**。又一个"不报错的 bug"。

### Q7
1. ①**不存档** ②**不清场** → 旧棋子全留在场上；回主菜单再点"新游戏"，`InitGrid()` 里 `pieces = new Piece[width,height]` 直接覆盖引用 → 旧棋子变成孤儿 → **两套棋叠在一起**。
2. 根因不是顺序，是**一个变量回答了两个问题**：`gameState` 同时被用来判断"该显示哪个面板"和"该不该存档"。而这两个问题的答案集合**并不一一对应**（`Resolving` 时玩家明明在游戏里，却被判成"非 Playing = 皮肤界面"）。
3. ① Resolver 旧版的 `matchs` 和 `match` 两个变量 + `||` ② `GenerateSpecialPiece` 里 `bestPiece` 和 `p` 两个对象 ③ 想再开一个 `PieceState[,]` 数组 ④ 想用 `x > 2` 兜住"不确定是 1 还是 2"。
> 统一判据：**两个变量/数组/对象表达同一个意思 → 停下来。`||` 和 `if` 不是解法，是把 bug 藏得更深。**

### Q8
1. 因为这三处都是 **`gameState` 被置为 `Playing` 的同一时刻** —— 数组是满的、动画也停了，正好是 `IsBoardComplete()` 为 true 的时刻。
2. 会存出一个**有洞的棋盘**（`SaveData` 里 `if (piece == null) continue;` 会跳过硬洞，`LoadData` 只填有数据的格子）。读回来那些洞**永久留在场上，谁都填不上** —— 因为补位逻辑只在消除流程里跑。
3. 从"**整局**"缩到"**不到 1 秒的动画期间**"。而那 1 秒本来就存不了（数组满但动画在跑，存下去读回来会错位）。

### Q9
1. `private IEnumerator Xxx()` —— 返回类型是 **`IEnumerator`**。
2. 骨架：
```csharp
while (matchs.Count >= 3)
{
    ScoreManager.Instance.AddScore(matchs.Count);
    Sequence clear = grid.ClearPiece(matchs);
    yield return clear.WaitForCompletion();
    grid.RemovePiece(matchs);
    Sequence drop = DropSystem.DropPiece(...);
    yield return drop.WaitForCompletion();
    Sequence gen = grid.GeneratePiece();
    yield return gen.WaitForCompletion();
    matchs = MatchSystem.CheckAllMatch(grid.pieces, grid.width, grid.height);
}
```
3. 循环结束后：`GameManager.Instance.SetGameState(GameState.Playing);` + `SaveCheckPoint();`
> 只能有**一个**循环变量 —— 写 `matchs.Count >= 3 || match.Count >= 3` 就是死循环。

### Q10
1. **游戏没崩、没报错、画面正常，但玩家再也点不动了。** `gameState` 永远卡在 `Resolving`，而 `InputManager` 看到 `Resolving` 就拒绝一切点击。
2. **一个字都没有。** 这就是它最阴的地方。
3. 因为崩溃会给你行号和堆栈，**而"什么都不发生"什么都不给你** —— 你只能靠推理，而推理的前提是知道"解锁动作写在了最内层回调里"这件事很危险。
> 规则：**把"解除锁定"放在异步回调的最后一步，就是在赌这条链一定不会断。**

### Q11
1. `HashSet<Piece>`（从 `set.Add()` 的用法能看出来）。为什么要用它：`piece == null` 和重复块都会让同一个方块被入队两次。
2. 返回 **`bool`** —— 元素是新的返回 true，已经存在返回 false。
3. 同时完成**去重**（已存在就不入队）和**判断是不是新元素**两个判断。这就是这一行比 `Contains` + `Add` 两行写法高明的地方。

### Q12
1. **不需要动画、不需要 `transform`。** 整个过程就是"遍历棋盘、试每一个相邻交换、看会不会产生三连"——纯数组操作。
2. **`MatchSystem`**（它已经放着纯算法），或者单独一个 `DeadlockDetector`。**不能塞进 `GridManager` 的动画回调里**。
3. 和 `MatchSystem` 其他方法一样：`(Piece[,] pieces, int width, int height)`，返回 `bool`。
4. 死局被检查出来了，但没重排 → 玩家返回主菜单 → `IsBoardComplete()` 为 true → **这个死局被存进了存档** → 玩家下次"继续游戏"，一进去就是死局，**永远卡住**。
> 所以死局检测不只是"防卡住"，还和存档直接相关。
